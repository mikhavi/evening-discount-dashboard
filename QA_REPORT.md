# Проверка прототипа

Дата: 06.10.2026. Проверка проведена на локальном сайте в браузере, без подключения к 1С и кассе. Для исходной выгрузки дополнительно выполнен независимый пересчёт скриптом `tests/qa_independent.py`.

## Загрузка файла

| Сценарий | Результат |
|---|---|
| Файл `.txt` или другой тип | Отклоняется с просьбой выбрать `.xlsx` |
| `.xlsx` размером 0 байт | Сообщение, что файл пустой |
| Повреждённый `.xlsx` | Понятная ошибка чтения книги |
| Книга без листа с данными | Сообщение об отсутствии листа с данными |
| Заголовки есть, товаров нет | Сообщение об отсутствии строк с товарами |
| Нет обязательной колонки себестоимости | Название недостающей колонки показано в ошибке |
| Только нецелевые товары | Показано число пропущенных строк, план пустой |
| Титульный лист перед листом данных, заголовки на строке 3 | Данные найдены и обработаны |
| Некорректные остаток, цена, единица или время изготовления | Позиции попадают в исключения, в план не проходят |
| Включена настройка «Для „шт“ — только целые числа» | `0,25 шт` утки показано как ошибка выгрузки `FRACTIONAL_PIECES`; строка не направляется на бракераж автоматически |
| Настройка целого остатка выключена | Предупреждение скрывается; `0,25 шт` снова попадает в бракераж по порогу остатка |
| Готовность плана при исходной выгрузке | 54 кандидата: без обязательного согласования 47 имеют определённую цену и корректный код, 7 требуют сверки кода. При включённом согласовании до решений директора готовы 41, ещё 6 ждут согласования. Ручное подтверждение кассы больше не требуется |
| Порог `5,5 кг` на исходной выгрузке | Со знаком `≤` в плане 52 позиции, со знаком `<` — 53; правило на дашборде меняется вместе с выбором |
| Некорректное значение порога | Отрицательное или пустое число не применяется; остаётся последнее допустимое значение |
| Пустой или сокращённый штрихкод | Позиция остаётся в плане, код помечен для сверки до стикера |
| Ошибка новой загрузки после успешной | Предыдущий план скрыт, чтобы не принять его за новый |

## Границы правил

- Закрытие ровно в 20:00 отклоняется: нужен ненулевой период акции. Закрытие после полуночи принимается.
- Срок, заканчивающийся ровно в 20:00, отсекается до акции; в 20:01 и ровно к закрытию в 23:00 — как истекающий во время акции; в 23:01 товар может попасть в план.
- При настройках по умолчанию остаток 0,49 кг или 0,99 шт блокируется как бракераж; ровно 0,5 кг и 1 шт/порция тоже направляются на бракераж. Числа и знаки теперь настраиваются в интерфейсе: при выборе `<` ровно порог не относится к бракеражу, если нет иных ограничений. Настройки по умолчанию отличаются от слова «менее» в исходном регламенте.
- Цена 101 ₸ с обычной скидкой округляется вниз до 70 ₸. Если 30% скидки нарушают порог маржи, цена поднимается до ближайших 5 ₸ выше порога с `MARGIN_ALERT`; если минимальная цена не ниже старой, строка блокируется.
- Повтор кода в нецелевой категории не создаёт ложную ошибку для целевого товара.
- Ошибочные значения времени `12:99`, `24:00` и текст с вкраплением времени блокируются как некорректные данные.

## Исходная выгрузка и Excel

Исходный файл: 107 строк → 76 целевых, 31 исключена по категориям. При включённой по умолчанию проверке целого остатка из целевых: 54 к уценке, 19 истекают до 20:00, 2 — во время акции, 1 — ошибка `FRACTIONAL_PIECES`. Бракеражная строка одна и уже учтена среди 19 по сроку. В плане 6 товаров с `MARGIN_ALERT`, 7 со сверкой штрихкода.

В исходной выгрузке нет остатков ровно 0,5 кг или 1 шт/порция, поэтому включение этих границ в бракераж не меняет указанные итоги. На отдельной проверочной выгрузке такие позиции исключены из плана и показаны в бракераже. Если снять галочку проверки целого количества, остаток утки `0,25 шт` перестаёт считаться ошибкой и становится второй бракеражной строкой. Настраиваемые пороги добавлены после этого отчёта; приведённые числа относятся к значениям по умолчанию.

Независимый пересчёт подтвердил: стоимость акционного остатка по старой цене **729 005 ₸**, потенциал по новой цене **536 765,5 ₸**, стоимость остатков со сроком до акции по себестоимости **156 502,5 ₸**, во время акции — **19 990 ₸**. Проверены все 54 строки листа плана: категории, цены, остатки и штрихкоды. «Потенциал» остаётся в сводке и на дашборде; из рабочего плана эта колонка удалена. Вложенный образец книги пересобран текущим генератором: 7 листов, 54 строки плана, 47 строк готовы по цене и коду, одна бракеражная строка и одна ошибка `FRACTIONAL_PIECES`. В реестре ограниченных цен нет старой колонки ручного подтверждения кассы. Фильтры и закреплённые заголовки сохранены; штрихкоды в плане записаны текстом, включая пустой код.

После перевода расчётов в формулы пересобраны итоговая книга исходной выгрузки и демонстрационная книга. Проверено чтением XLSX с формулами и сохранёнными результатами: во всех строках плана новая цена является формулой, а для `MARGIN_ALERT` она ссылается на утверждаемую цену листа «Цена скорректирована». В обоих реестрах `MARGIN_ALERT` цена −30%, порог +5% и фактический процент скидки записаны формулами. Цена к продаже оставлена редактируемым числом для решений директора. Значения сводки по старой и новой цене совпали с суммами по строкам плана. Оба вида экспортированного файла повторно приняты механизмом загрузки исправленного реестра: 6 строк исходной выгрузки и 2 строки демонстрационной. В отдельном реестре изменение одной цены на 5 ₸ обнаружено при обратной загрузке в обоих примерах.

После добавления отдельной выгрузки «Готовы к наклейке» проверен файл, созданный текущим генератором: при автоматическом режиме в нём 47 позиций, при обязательном согласовании без решений директора — 41. Каждая строка имеет отметку готовности, корректный штрихкод и формулу цены; в файле нет товаров, ожидающих сверки кода. Независимая проверка исходного файла и итоговой книги обновлена под восьмиколоночный план без «Потенциала» и проходит.

Отдельно проверено согласование цены: невалидные цены и пустое имя отклоняются; решение после повторной загрузки того же файла в тот же день восстанавливается. Скачанные после согласования Excel-файлы отражают новую цену и статус. После изменения цены нужно скачать новый JSON для касс.

Переключатель порядка согласования проверен в интерфейсе на исходной выгрузке. При выключенном согласовании план показывает 47 готовых по цене и коду, 0 ожидающих директора, а кнопка JSON доступна для 6 позиций. При включённом — 41 готовую, 6 ожидающих директора; пустой кассовый файл не предлагается. После обратного переключения исходное состояние восстановилось. На карточках цен нет галочек настройки кассы. Нажатие на скачивание JSON ранее вызвало уведомление о подготовке 6 цен и о том, что передача через API не выполнялась. Содержимое скачанного JSON в браузере этой проверки не считывалось; для приёмки реальной интеграции нужны схема кассового API и тестовая касса.

После удаления колонки ручного подтверждения формирование полной Excel-книги и отдельного реестра `MARGIN_ALERT` проверено в браузере: оба действия завершились сообщением о скачивании, ошибок JavaScript не было.

Обратная загрузка исправленного реестра проверена в браузере. Старый выгруженный реестр с неизменёнными шестью ценами и лист «Цена скорректирована» из итоговой книги открыли окно «Цены не изменились» с отдельным подтверждением. Реестр с одной исправленной ценой показал сравнение `2 940 → 3 000 ₸` до применения. Без имени директора применение отклонено; после ввода имени карточка и план показали `3 000 ₸` и сохранили решение для отдельной тестовой копии выгрузки. При автоматическом режиме сохранилась только одна изменённая цена; после включения обязательного согласования остальные пять ждали директора. Повторная загрузка того же реестра показала предупреждение об отсутствии изменений, а подтверждение утвердило все шесть цен. Цена `2 000 ₸` для стейка отклонена как ниже минимума `2 940 ₸`; исходная книга 1С, загруженная вместо реестра, отклонена из-за отсутствия нужного листа. Изменения проверялись на отдельной копии выгрузки, чтобы не менять решения пользователя для исходного файла.

## Границы прототипа

- Согласование сохраняется только в браузере на конкретном устройстве. Проверки роли директора и передачи решения между устройствами пока нет.
- JSON для касс готовится локально и не отправляется в систему касс: адрес API, схема, авторизация и идентификатор магазина не предоставлены. Приложение не заявляет, что цена уже применена на кассе; для этого нужен технический ответ кассовой системы.
- В исходной выгрузке есть только время изготовления. Расчёт предполагает изготовление в день среза; для реальной эксплуатации нужна полная дата и время.
- Некоторые формально корректные `.xlsx` от сторонних генераторов с нестандартной структурой XML не читаются ExcelJS. Приложение показывает ошибку и предлагает пересохранить файл в Excel или 1С.
- Фактические продажи и списания в выгрузке отсутствуют: потенциальная выручка не означает подтверждённую экономию.
